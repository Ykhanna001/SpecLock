SpecLock app map

A reference route through the local, browser-only Northstar Notes review flow. This page is a source guide, not an interactive tutorial or evidence of a learner code tour.

How the review flows

SpecLock evaluates a user-entered proposal against a fixed set of baseline requirements. Its three scenario buttons select test categories only and do not supply proposal text. The four outcomes are Definite conflict, Potential conflict, No conflicts detected, and Unable to assess. Scenario categories and a small deterministic rule set produce evidence-backed results; review versions and decisions are kept in browser sessionStorage.

Reference route: follow a review

  1. src/App.tsx — find runReview and the Review Proposal button. The handler collects the current proposal and scenario, then requests a version.
  2. src/state/reviewStore.ts — find nextReviewVersion. It calls the engine and appends a version while preserving any linked parent review.
  3. src/review/reviewEngine.ts and src/review/evidence.ts — find reviewProposal and assertFindingEvidence to trace fixture/rule selection and validation that each quote is present in the proposal and baseline.
  4. Return to src/App.tsx and find FindingResult, ReviewHistory, and ReviewComparisonPanel to follow how outcomes, history links, and parent comparisons appear.

To change this, start here

  • Baseline text and stable IDs: src/data/northstarBaseline.ts.
  • Seeded demonstration proposals: src/data/seedScenarios.ts and corresponding fixtures in src/review/fixtures.ts.
  • Custom deterministic classification and fallback: src/review/reviewEngine.ts.
  • Evidence invariants: src/review/evidence.ts.
  • Version history and refresh persistence: src/state/reviewStore.ts.
  • Workspace layout and responsive behavior: src/App.css.

A practice to reuse

The definite-conflict acceptance case connects the Northstar baseline IDs and exact source text to the custom proposal result and UI evidence assertion. In another project, make a requirement observable, preserve its stable reference, and test that the displayed evidence is actually present in the input before trusting the classification.

Run and snapshot

From the repository root, run npm install and npm run dev, then open the local Vite URL. No backend or network service is required for review behavior.
